# VH-238 — A file chosen again is read again, and every choice asks about the file the page read

## Intent

Analyst C's one rank 1 finding (C-01) and its sibling (C-02): the page asks "is the chosen file the one that was read?" by comparing the file input's live list with the file it read, and Chrome gives the list new objects, with no `change` event, when the same file is picked again. After that a trim or output change re-checks nothing and Create makes the old trim; and a file that failed to read, or was copied again whole, cannot be tried again. C-08 rides with it: a read that timed out is told to choose a different file, where the page's own "Try again" sentence fits.

## Acceptance criteria

- The chosen file is held in one place, set where the page reads it, and every handler that asked the input's live list asks that instead.
- Picking the same file again in the browser's chooser reads it again, as a new choice does; a chooser opened and closed with nothing picked changes nothing.
- A read that took too long takes `failure.tryAgain` as its next step, the sentence the table already holds.
- No word, sentence, key or control added or changed in any language; no `docs/` line; no runtime dependency; no test deleted, skipped or weakened.
- `npm run check` green with no new skip; read in Chrome on the MacBook Pro, the reading recorded; what only a person or the Mac Pro's walk can read is named, not claimed.
