# VH-251 — The interface rebuilt in React and Carbon React: every step, state, dialog and language, the theme at AAA, behaviour checks as accessibility journeys

## Intent

The owner chose the app opinion's full kind, with React and Carbon
React, and asked for the app rebuilt "as though it was made with this
stack in the first place". Today's interface builds the page by hand in
59 files; this item rebuilds it as React components on Carbon React,
over the core and adapters VH-250 laid out, keeping every behaviour,
word and language the specification and the record require.

## Acceptance criteria

- Starts only after VH-250, which the owner's approval of the specification's correction (asked in VH-249) already gates, and once Name Graphics' pilot (VNG-15) has proved React, Carbon React and the accessibility gate on the root install.
- First, an inventory of every test case that touches today's interface, by behaviour: each assertion, including those that read the page's HTML and TypeScript (`test/screen-text.test.ts` among them), mapped to where it will live — the core under Vitest, or a browser journey in tests/a11y/project.mjs (the pack's test split, no jsdom). Each is ported with its code; no test is deleted or skipped; counts alone cannot show a substitution, so the inventory is the evidence and the decision cites it.
- The ported journeys in the gate from the start: the new interface is built at its own entry beside today's, and from the commit that ports a journey, that journey and `npm run a11y`, the standard command, run in the Finisher's `npm run check`, which CI calls before every publish, against the new interface. The gate's tests/a11y/project.mjs and coverage file declare the new interface as it stands at each commit, complete for what it has (its states, journeys and features, each feature present or absent with its evidence), so the standard command runs whole and passes, never by `--grep` or a partial run; each port adds its declarations. VH-249's baseline stays a dated record beside them. An old assertion leaves the gate only in the switch commit, and only once its port has run green in the gate; no publish runs with an old assertion gone and its port outside CI.
- The interface rebuilt in React with Carbon React's components, the forms starter's entry merged into the Finisher's, one reviewable journey at a time, each its own commit and review: choosing the video and its kind, the trim, the title card, the closing, the output, the run with its progress and cancel, the save, the failures, help, feedback and the accessibility statement, the language switcher with en-GB, zh-Hans and ms-MY, offline. Validation, timing, rendering, persistence and export stay plain TypeScript; React owns the controls.
- The theme from the pack's src/ui/theme.scss fitted to the Finisher's brand tokens (if it reuses code VNG-15 wrote, that code moves to `shared/` by a parent item first and this line reads "blocked: UVT-n"), which stay the brand's: text at 7:1, the 3 px focus outline, 44 px targets, transitions stopped under reduced motion; the rendered Carbon controls tested in every theme the Finisher offers (light, dark, the blue band); IBM Plex bundled from the root install.
- The switch: one commit moves the live entry point to the new interface and removes the old interface's files and the assertions that read them, only when every inventoried assertion has its port green in the gate, the gate's declarations hold the baseline's whole feature, state and journey set, and the standard command passes over it, meeting or beating VH-249's baseline; from it the gate's journeys read the live entry. The preview stays on the old interface until then.
- The Always rules hold: no media egress, streaming not buffering, numbers in `src/config/` or a token, the redacted diagnostics, nothing persisted that the rules forbid.
- The gate green, `npm run typecheck` running all five projects UVT-7 defines; `node tools/check.mjs` 0 failures; each step's Checked line.
