# VH-250 — The forms kind's layout: `src/core/` framework-free, src/adapters/, `src/ui/`, the boundaries, Knip and the typecheck split, every test moving with its code

## Intent

The app opinion's forms kind lays an app out in three areas the
boundaries enforce: a framework-free core, adapters to the browser and
the outside, and the interface. The Finisher's 42,000 lines are moved
into that shape before its interface is rebuilt (VH-251), so the
rebuild lands on code already in place, and the media pipeline's proven
behaviour is carried, not rewritten.

## Acceptance criteria

- Starts only when the owner's disposition of the specification's correction (asked in VH-249) is recorded as a decision: its backlog line is `[!]` until then, and no React source (the forms starter's entry, React or Carbon React) enters the tree before it.

The pack's tool-local `tsconfig.base.json` is not copied; the Finisher extends the root's (UVT-7).
- The Finisher takes up the root's offered compiler checks and lint layers under its own ID, mending its own code: today `erasableSyntaxOnly` raises 25 errors and two escape rules 10.
- The layout: a framework-free core (the loudness and audio planning, the config, the pure parts of media and i18n, the interface's logic now in `src/ui/`), adapters (WebCodecs and mediabunny, OPFS, the workers, offline and the service worker, the logger's sinks) and the interface, still today's until VH-251. The core project has ES libraries only and empty ambient types. `src/config/` and the protected audio files either keep their paths, listed as core areas, or move with the rules file's lines and protected paths rewritten and signed in the same step; a moved protected audio file re-runs the EBU harness.
- The entry: the forms starter's React entry takes a basename of its own, never `main` beside today's `src/main.ts`: TypeScript drops a `main.tsx` for the `.ts` of the same name, even when both are named in `include` (Codex, with TypeScript 6.0.3 in both trial tools). A check proves the compiler and ESLint's project service read it. Today's page stays the live entry and the preview.
- The starter's example model, validation and persistence adapter never enter as they are: its sample form keeps typed names in local storage, which nothing in the Finisher asks for, so it is removed or replaced before the commit that would carry it.
- dependency-cruiser's allowlists from the real imports: mediabunny allowed where the adapters use it, the shared core modules named one by one (some use browser APIs), the spike and acceptance pages their own entries; a test proving a legal shared import passes while an interface import from the core, and any import of the other tool, fails. Knip clean with every real entry named: the page, the workers, the service worker, the spike and acceptance pages (the manual gate), `test/`, the scripts. `npm run typecheck` running all five projects UVT-7 defines (core, app, workers, tests and the accessibility pack's tests), `npm run boundaries` and `npm run deadcode` in the gate.
- No test deleted or skipped (rule 7): every test file still runs and passes; the gate at 2,001 passed and 1 skipped, the skip still EBU cases 7 and 8, or more passing.
- The gate stays non-mutating: the build is checked into a temporary folder (`npm run check:build`), never `dist/`; the Xerte build still checked.
- `node tools/check.mjs` 0 failures; each step its own commit with its Checked line.
